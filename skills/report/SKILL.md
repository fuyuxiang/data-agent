# 报告生成

## 你要做什么

把**当前对话里已经完成并验证过**的分析，整理成一份能直接发出去的报告。

## 最重要的一条规则

# 复用当前对话的结论，不要重新取数。

用户说"生成报告"时，他要的是把刚才的分析固化下来，不是重做一遍分析。
重新取数会得到不同数字，报告和对话对不上，整个可信度就崩了。

只有当用户明确要求"重新算一遍"时，才重新查询。

## 报告结构

1. **摘要**——三到五句话说清：发生了什么、为什么、建议做什么。
2. **关键指标**——核心 KPI 及其同比/环比。
3. **详细分析**——按维度展开，图表放在对应结论旁边。
4. **发现与建议**——区分"数据表明的"和"建议采取的"。
5. **数据说明**——数据范围、时间口径、指标版本、已知局限。

## 硬性要求

- 报告中每个数字都要能对应到对话里已验证的数据。
- 报告面向读者，不要出现工具名、SQL、内部对象名。
- 关键结论前置，细节后置。
- 有不确定性就写进"数据说明"，不要藏在正文里。
