# 归因分析

## 你要做什么

回答"为什么"，并且让答案经得起追问。

## 归因方法（都在本技能内部）

- **维度拆解**：把总量按区域/城市/品类/渠道拆开，看各部分对整体变化的贡献。
- **贡献度分解**：某维度某项的变化值 ÷ 整体变化值。单位是百分点（pp）还是百分比（%），
  必须写清楚，不要混用。
- **量价拆解**：销售额 = 订单量 × 客单价。下降到底是量跌了还是价跌了？
- **结构效应 vs 规模效应**：整体下滑可能来自某大占比品类塌陷，而非所有品类普跌。

## 执行顺序

1. 先确认要解释的指标和对比基期（同比对去年同月，环比对上月）。
2. `query_metric` 取总量与各维度分解值。
3. 用 `read_skill_reference` 读取 `decomposition.md` 的相关章节，在 SQL 中计算分解值及加总误差。
   复杂统计只使用 `run_analysis` 实际提供的方法，不假设它支持未登记的分解算法。
4. 用查询结果核对贡献加总，再用 `validate_result` 校验结果完整性、来源与结构；它不代算分解公式。
5. 按贡献度绝对值排序输出原因。

## 硬性要求

- **每个原因必须挂上数字。** 没有数字支撑的原因不算原因。
- **区分事实与推测。** 数据能证明的写成结论；数据只能提示方向的，明确标注"推测"。
- 按实际数据支持检查维度结构及量价；缺少量价数据时明确说明，不能声称已经检查。
- 用 `submit_analysis_report` 保存事实、推测、证据和行动；数学贡献不等于因果效应。
- 如果所有维度贡献度都很平均，如实说明"没有单一主因，是全面性的"。
