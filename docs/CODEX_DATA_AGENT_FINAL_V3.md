## 1. 产品目标和边界

目标产品是“受治理的自主数据分析与数据科学工作台”。用户通过自然语言提出问题，Agent 在授权数据和预算内自主寻找资料、理解语义、提出并修正分析计划、执行 SQL/API/Python、验证结果、产出可追溯成果，并支持后续追问、局部重算和任务恢复。

### 1.1 自主性要求

- 分析步骤不能固定为“理解→探查→SQL→验证→Python→报告”。
- 简单问题走短路径；复杂问题按执行反馈持续规划、重规划和并行分解。
- 固定的是权限、预算、动作记录、工具协议和发布验收，不是方法选择。
- 可以调用已发布的确定性工作流，但不能强制所有探索任务进入预定义 DAG。
- 模型可以改变实现路径，不得静默改变目标、数据范围、指标定义或强制验收规则。
- 应展示目标、计划变更、实际工具事件和简短决策说明，不展示或记录用于展示的模型原始私有思维链。

### 1.2 必须覆盖的用户功能

目标澄清；选择数据源；上传文档与数据文件；数据和指标发现；探索、SQL/API 取数、统计/异常/预测/实验/情景分析；按需生成代码；计划与假设管理；有限修复；独立验证；结论/看板/报告；查看 SQL、代码和证据；Word/PNG/数据导出及保留已有 PPT；历史结果回放；重新分析；增量追问；暂停、取消、重定向和审批；记忆与技能维护；有授权的定时或更新触发分析；审计与评估。

### 1.3 部署范围、可实现边界与真实引擎基线

PB/EB表示接入仓库的数据存量，不代表每个问题都应扫描这个规模。任务实际扫描量、join/shuffle量、结果大小、并发与时延分别配置和实测。

控制面自研，数据面复用现有平台：Flask/Vue、模型决策、任务状态、授权、证据和小成果在应用侧；大表读取、过滤、聚合、关联、特征计算和大型模型任务在数仓/分布式计算侧。禁止在应用服务器复制整仓、整表或把百万分区索引每次加载进模型。

两种可运行部署profile：

- `local`：保留桌面/小文件体验、单所有者SQLite和有界隔离Python，不宣称PB/EB计算能力。
- `warehouse`：应用控制面可以仍为单主SQLite（有明确并发与容量边界），连接真正远程SQL和批作业平台；业务数据和大结果始终留在数据域。不能把保留SQLite曲解为数据计算也必须单机。

本次必须完整实现并测试一条参考数据面：Trino远程SQL + Iceberg表/授权catalog + Spark远程批作业（通过Livy REST）。提供锁定且相互兼容的版本、驱动、镜像、catalog与测试配置。不要任意拼接各产品latest。已有客户平台明确后，优先为实际平台适配同一契约；参考平台不是强制迁仓方案。

先做宿主 CPU/内存/磁盘、网络、容器/权限预检，为参考环境提供可复制的最小资源说明；不足时明确 BLOCKED，不循环启动至宿主 OOM。参考SQL环境至少协调器+两个worker、真实分区列式数据；Spark至少driver+两个executor并实际执行分布式stage。单容器多进程只证明功能，不等于跨主机容灾或规模认证。参考环境需支持远端结果表/对象前缀、作业状态、取消、统计、权限和测试数据；不得只写一个抽象BaseConnector。

保留原PostgreSQL/MySQL/SQL Server/文件/API等已实现功能，不一次性承诺所有云数仓原生适配。BigQuery、Snowflake、ClickHouse、Doris、HiveServer2等没有实现/联调的类型必须标NOT_IMPLEMENTED或UNVERIFIED，而不是把SQLAlchemy URL配置成功当功能完成。

高并发/多副本HA应根据控制面负载和SLO另行确定。不要仅因源仓达到EB就强制引入Kafka、Redis、Kubernetes、多活PostgreSQL；也不要将多个应用实例指向同一SQLite卷。客户要求HA时必须补实际共享状态、租约与故障演练，不能宣传预留接口已实现。

本次不重建PB/EB存储系统、通用分布式优化器或无限大模型训练平台；也不保证任意数据源支持断点续查、精确成本估算、行级权限和永久历史复现。缺失的能力必须进入探针与路由决策，安全关键项不支持则拒绝对应操作。

1. 原文“模型思考过程”改为面向用户的“需求理解依据/决策摘要”，保留流式与折叠交互；不要求模型提供私有内部思维链。必须在产品说明和测试中记录这个解释，不能伪造推理日志。

### 兼容原则

内部函数/私有端点没有稳定兼容要求时，迁移全量调用者后直接移除。公开 API/CLI、保存的 Workflow/Skill 工具名、数据格式及历史成果分别调查，不要混在“旧代码都保留”中。

有必要保留的兼容对象登记：使用者、旧→新映射、当前授权、资源约束、测试、owner、移除版本/日期或可核验事件。适配层只做格式与路由转换，不包含第二套查询/推理/权限实现。没有依据的永久兼容开关不允许；尚未安全解决的外部消费者问题必须明确报告。

程序代码可退役，用户历史与数据库迁移链不因无当前 import 而删除。旧结果导入新目录时标明 `legacy_unverified` 与已知范围，不能自动获得正式已验证状态。


## 3. 架构形态与数据面强制约束

继续采用模块化产品，不重建无关平台。唯一主Agent负责分析决策；确定性Runner负责运行和等待；ExecutionRouter/ToolExecutor根据计划、能力与安全策略确定执行位置。不要增加另一个模型规划器与主Agent争夺控制。

```text
现有Vue对话/需求确认/过程卡/成果Tab
                  |
        Flask API + 持久运行/事件/控制
                  |
   自研AgentLoop / Context / Plan / RunStore
                  |
      ToolExecutor + ExecutionRouter
       /           |              \
 WAREHOUSE_SQL  REMOTE_SPARK  BOUNDED_SANDBOX
       |           |              |
  现有查询引擎   现有批计算集群    小型已验证数据
       |           |
  原数仓/数据湖/授权结果区/原生快照
       |           |
  小聚合结果、统计、schema、结果引用、证据 -> 控制面
```

API/指标服务是独立执行路由，仍遵守相同范围、完整性、预算、证据协议。建议新内核放在`backend/agent/`，新增引擎适配、查询规划/准入、远端结果管理模块；旧入口真实调用新模块，不能另建不被使用的v2演示。

### 3.1 最重要的十条不变量

1. 大仓数据默认不离开数据域。SQL应在仓内完成过滤、投影、聚合、窗口和必要关联；不是在模型或Pandas里做这些大规模计算。
2. `DatasetRef`/远端关系是第一等输入，`pd.DataFrame`只能作为有界执行后端的内部对象。所有query/profile/clean/analysis/chart/export路径都必须检查执行位置，不能旧入口偷拉全表。
3. “完整分析”指按确认范围完成必要计算，不要求把范围内所有原始行复制出来。一亿条记录精确聚合成100行，完整聚合结果就是100行。
4. 大型完整输出在远端受控结果表或对象存储中，返回引用与分页接口。已登记SQL计划或query_id不能冒充已物化、可长期读取的结果。
5. 本地传输同时受行数、字节、单值大小、解码内存、列数、时限和任务累计出口预算约束；默认配置只是可调初值，不是容量保证。输入大小未知不能先完整读取再判断。
6. Arrow/Parquet/流式是格式和传输手段，不等于无需内存、不等于分布式、更不等于允许PB全量下载。Spark的collect/toPandas同样必须有门禁；静态检查不能替代运行时配额。
7. 大范围多源关联只能在已授权的联合查询引擎/计算集群中执行；无共同数据域和合理传输路径时明确阻塞。不能将‘不支持’改成拉回本机join。
8. 来源只读与结果区写入分开。受控物化服务可以用专用账号写run专属scratch表/前缀；不向模型开放通用DDL/DML或源表写权限。物化、清理、导出均有预算、TTL、ACL与审计。
9. 任务预算涵盖探索、预检、验证、重试、模型、并行子任务、物化和导出。行数LIMIT、抽样或EXPLAIN输出不是资源上界保证。
10. 声明与实测分离：能力探针、真实引擎集成、真实模型任务、真实规模压测分别出证据。未验证PB/EB性能时只能说‘面向PB/EB数仓接入架构’，不能说‘已验证EB能力’。

### 3.2 DatasetRef最低语义

```text
ref_id, kind(logical_relation|remote_table|remote_objects|bounded_file),
source_refs, engine_id, catalog/schema/table or object_manifest_ref,
snapshot_set, source_time/watermark, schema_ref, grain,
query_id, query_hash, contract_version, policy_version,
computation_state(planned|running|complete|failed),
result_completeness(complete|partial|unknown),
accuracy(exact|approximate|sample_based|unknown),
requested_scope, actual_scope, sample_method/error_metadata,
row_count(known|unknown), encoded_bytes(known|unknown),
preview_ref, provenance_ref, retention_until, owner/ACL
```

范围完整性、数值精度和结果可用性三个维度不能合成一个布尔值。近似算法可能扫描完整范围但仍非精确；精确Top N可以是完整请求；系统截断不是完整。

大表只存table/snapshot/query级血缘和有限关键结论映射，不为每一行建立中心化证据节点，不为获取全仓hash再扫一次全仓。远端对象manifest分页读取；快照保留由平台策略保障，过期不能伪称可复现。

### 3.3 引擎能力契约与生命周期

每个适配器实现真实的`discover/search/describe/estimate/submit/poll/cancel/result_ref/read_page/stats/reconcile`中其宣称支持的项，并明确unsupported项。能力矩阵包含：方言、认证委托、行列授权、过滤/聚合/关联下推、估算的指标与可信度、原生限额、异步ID、取消、掉线语义、结果保留、快照、远端物化、抽样精度。

SQLAgent选择逻辑查询和分析目标；引擎自身优化物理执行。执行器通过EXPLAIN/dry-run核验必要的范围和成本，不自行实现通用CBO，也不以LLM说‘已优化’为证据。

Trino客户端必须由独立于浏览器的执行组件继续读取nextUri/完成协议。query_id不是永远可恢复的后台Job；客户端长时间停止、coordinator故障、结果保留过期都可能失效。持久保存查询、最后状态与结果区标记；恢复先核验，必要时在同一有效快照上用新attempt重跑且计费，不能保证精确执行点恢复。Livy批作业同样核验batchId/appId和结果manifest，不仅信任本地状态。

### 3.4 参考环境与安全实施

测试并锁定Trino+Iceberg+Spark/Livy的共同catalog/对象存储或明确转换路径，实际证明Spark能消费Trino产生的授权结果引用，不靠同名字符串假装互通。

生成代码只能运行在任务隔离、资源受限、权限收窄的环境。远端Spark driver/executor可能接触数据凭据；不能将‘凭据不在prompt’当隔离。应使用平台真实身份、scoped临时凭据或专属授权输入区、网络/目录限制，禁止通过原始存储路径绕过行列策略。Livy的proxyUser/doAs必须由服务端绑定且受集群规则限制，模型不得设置。

若平台不能安全执行任意PySpark代码，生产仅开放经审核的分布式JobSpec/方法模板；任意小数据分析代码仍在安全sandbox运行。必须实现可用分布式方法而非直接返回unsupported，并明确哪些算法是bounded-only；不得以安全限制为借口用采样数据冒充全量训练。确需动态分布式代码时，真实隔离未通过则该能力BLOCKED，不虚假完成。

### 3.5 模块边界、主路径与最小物理部署

优先在现有仓库形成以下职责，不要求每项独立微服务或每项建立一个 Agent。目录示例需要与当前代码核对后适配，不允许保留两份同职责实现：

```text
backend/agent/               模型协议、上下文、唯一循环、计划、执行、Runner/Store
backend/services/data_plane/ DatasetRef、目录/语义、准入、路由、连接器、作业、物化
backend/services/validation/ 规则检查、质量评分、验证覆盖与发布条件
backend/services/results/    Claim、ResultManifest、版本、渲染、授权读取
backend/api/                 原产品 API / SSE / 控制 / 必要薄兼容
frontend/src/                原工作台、四段确认、动态过程、三类成果、证据、历史
skills/                      有输入/输出/权限/验证合同的已审核分析方法
scripts/                     迁移、真实测试、清理审计、部署与恢复工具
```

API/业务门面可维持现有目录，算法库和导出库在原位复用亦可。只为一类的一两个函数新建空框架层没有价值。ModelAdapter、DatasetRef、Action、ValidationResult、ResultManifest 必须唯一；不在多个目录复制类型与 Enum 后靠字段相似性对接。

最小物理部署是 API/界面、Agent Runner、可信查询/作业执行组件、隔离小数据执行环境，加现有控制状态与对象存储；数仓/计算集群为外部平台。初期可为一个模块化应用的数个进程。不得为了“先进”默认引入新消息中间件或微服务网格。

`AgentLoop/ModelAdapter/Plan` 等核心模块不得依赖 Flask request/session/current_app；运行上下文由 API 或调度入口构造，随后可在独立 Worker 中重建。HTTP 客户端断开只影响事件订阅。SQLite profile 保持单控制状态所有者，通过受限 JobSpec 协议调用独立执行组件；不要声称普通网络共享 SQLite 提供多活。

### 3.6 三类计划各司其职

1. **任务契约**固定用户目标、数据范围和完成要求。
2. **分析计划**由 Agent 滚动修改，保存版本、假设、证据和依赖；可短路径、分支或并行。
3. **查询物理计划**由数据引擎优化，系统检查而不自行重建分布式优化器。

默认一个主 Agent；摘要或字段解释调用可以共用 ModelAdapter，不必变成多 Agent 平台。现有确定性工作流允许用原有调度数据结构，但实际动作必须接入同一执行/预算/产物层。Plan 图不是要求所有分析预定义为固定阶段。

### 3.7 能力可用性与可实现性门禁

M0 即建立参考环境版本兼容表、资源预检、模型能力和授权输入清单。参考数据面缺少某组件时不先编造服务返回；可以完成其他实现并标 BLOCKED。目标平台未知不妨碍完成参考路径；缺少目标环境也不允许把目标适配器空函数记 IMPLEMENTED。

预算预留是控制面准入，实际限制仍需引擎/沙盒落实；取消延迟、未知成本、硬限额支持情况分别记录。精确规模证据必须实际执行，不允许通过改元数据或 scale-factor 给测试“扩容”。

所有单次回传与累计数据出口都设默认可配置上限；给开发参考配置而非通用生产容量承诺。对本地内存的估算不能精确预测一切，因此预检查之外必须有实际进程/cgroup 限制和失败状态。解析文件、图表渲染与 Python 同样受限，不能在返回前完成无界加载才检查大小。


## 4. R01–R21 全部必交需求

### R01 — 按范围复用、真实接入并完成等价替换

建立当前功能/接口/数据格式清单，运行可用基线测试。将上述路径的改造落点写入追踪矩阵。新内核必须被现有聊天、团队、工作流和调度入口实际调用或经明确适配使用；不能只新增类而原产品仍跑旧循环。

保留中文工作台、必要本地资源、受支持的数据与成果格式、图表和导出。内部调用者全部迁移到正式路径；公开 API 只保留有明确消费者或兼容承诺的薄适配层，否则退役并同步文档。兼容层不准包含独立 Agent 循环、绕过权限的旧查询或第二套成果生成。安全修正需迁移说明与回归测试，不为兼容继续漏洞。

无模型时保留数据浏览、历史查看与明确的确定性诊断能力即可，不要求保留原来的第二套伪 Agent 流程。需要保留确定性查询入口时也走同一授权/Action/结果协议，显式标 local_deterministic；绝不自动切到旧 _run_local 并伪装自主规划或正式验收成功。

### R02 — 完整模型协议与自研决策循环

实现统一 ModelAdapter，复用现有 provider 配置和凭据，不另建重复配置系统。最低必须真实支持当前 OpenAI-compatible Chat Completions；追加一个独立的主流原生协议适配器（OpenAI Responses 或 Anthropic Messages），二者择一并完成实现、协议测试及可配置真实联调。不要只改 base_url 就声称支持不同协议。执行时查询相应官方文档，固定兼容版本。

规范化消息、文本块、工具调用、工具结果、usage、finish_reason、refusal、错误与中断。保留工具调用与结果配对；支持一轮多调用、Unicode、分块 JSON、结构化输出、可选图像输入能力协商。模型名和上下文容量可配置，不能把某个未来模型硬编码成必要条件。

必须处理正常结束、请求工具、token 截断、拒绝、网络中断、空输出及无效参数。流式工具参数只用于缓冲展示，不在完整接收、解析、校验和持久化前执行。不把截断输出修成一条未经确认的新敏感动作。

AgentLoop 支持工具批次、澄清、等待、完成请求与受限终止。模型不调用工具不代表通过验收；无数据的一般说明可以正常回答，但不能带正式数据分析已验证标签。动态分析步骤不能写成固定阶段数组。

有能力的模型可按配置使用不同推理预算；默认单一模型也必须完整运行。使用轻量模型做摘要或分类时，走相同用量与数据出站约束，不能泄露不允许发送的内容。

### R03 — 任务契约、持续规划与假设管理

实现版本化 TaskContract：目标、时间区间/时区、统计粒度、指标引用、数据范围、交付要求、预算、已确认假设、未确定事项与验收条件。

用户重点约束不能由模型静默覆盖。以原需求默认交互为准：新分析先生成四段需求理解卡，用户可编辑并进行一次显性确认；确认后即使简单问题也可走短执行路径，不强制额外分析步骤。卡片状态、重新描述回欢迎页、生成中隐藏按钮、确认后锁定都必须实现。工具策略、预算预授权在确认的契约中确定，不为所有任务另加SQL/计划/结果三次审批。重大新歧义不得静默改范围，可阻塞并要求通过明确契约修订解决。

实现结构化 PlanRevision、任务依赖、状态、输入/输出引用、成功条件、Hypothesis 及支持/反对证据。支持添加、取消、替换任务；证据推翻旧假设时，记录修订原因并使相关下游产物失效。更新使用 expected_version 防止并发覆盖。

计划图可以在每个版本内是 DAG；循环改进通过新版本/新尝试表达，不制造无穷依赖环。简单任务允许直接执行，复杂任务只细化近期动作。检查无进展、重复工具结果、连续修复失败和预算耗尽，合理终止。

模型不得删除强制安全规则、降低既定质量标准或把全量目标改成抽样目标。任何范围变化必须留痕，重大变化等待确认。

### R04 — 持久化运行、等待、恢复、取消

在现有数据库迁移机制中新增必要关系表和约束，不只把全部新状态放进无并发控制的一个 JSON。可按实际设计合并对象，但必须实现：

- agent_runs、contract/plan revisions、decisions、actions、attempts、typed jobs；
- 可续传 events、outbox/wakeup、budget reservations、approvals；
- 结构化数据集/成果/证据/验证版本及必要引用约束。

状态分离：execution_status、outcome、quality_status、stop_reason。支持 queued/running/waiting_input/waiting_approval/waiting_job/paused/cancelling/finished/failed/cancelled 等明确状态；完成与部分完成、质量通过与未知不能混为一谈。

运行不依赖浏览器连接。API 创建 run 后，Runner 领取执行；SSE 仅订阅持久化事件。客户端断线后任务按契约继续，重连使用 Last-Event-ID 或游标补读，不重新提交整条用户消息。

执行外部动作前，先持久化完整 decision 和 action，原子预留预算并写入 outbox；完成后先保存结果与引用再恢复模型。事务不能跨越模型请求或长计算。

用明确 job_type + JSON spec + handler registry 代替只能驻留内存的工作闭包。长作业提交后返回 ACCEPTED/job_id，等待时释放执行资源；完成事件或恢复扫描使 run 继续。禁止让模型高频轮询耗尽 Token。

区分 stable logical_action_id、attempt_id、external_job_id；同一逻辑动作重试稳定去重，参数实质改变创建新动作。不能用 SQL 文本哈希冒充动作身份。

实现领取租约、心跳、接管代号（fencing epoch）和过期写入拒绝。SQLite 模式仍保持单个应用状态所有者；不得取消实例锁后假称可多节点并发。独立执行进程通过明确 IPC/job 协议工作。

重启后核验外部作业及结果：已完成则复用、运行中则等待、明确未提交才提交、无法确认则 OUTCOME_UNKNOWN。对未知副作用不盲重试。只读重跑也记录重复成本和快照改变。

暂停不派发新动作；取消真实传递给数据库/计算执行器。区分“取消请求已接受”与“外部计算确认停止”。支持等待期间用户补充或修订契约，旧结果只能按版本匹配接纳。

### R05 — 统一工具执行、参数、权限与预算

建立 typed ToolSpec/ToolResult：输入输出 schema、错误码、读取/修改性质、幂等语义、超时、成本、产物类型、可用范围与可取消性。Pydantic/JSON Schema 等基础库可以使用。

所有执行入口必须检查 effective_tools = 用户策略 ∩ 当前任务范围 ∩ Skill 允许工具 ∩ 子 Agent 允许工具 ∩ 工具运行条件。只对模型隐藏工具不是授权；直接构造调用也必须拒绝。TESTING 不得自动授权生产安全测试。

模型不得设置 actor、tenant/workspace 身份、权限、approval_status、预算余额、可外发级别。执行上下文由服务端绑定，不能信任客户端传来的同名字段。

预算涵盖主 Agent、子 Agent、反思、摘要、修复、工具执行、SQL 资源和计算任务。并发前原子预留，完成后结算；未知价格标 unknown，不伪造准确成本。至少有时间、调用次数、Token、并发、结果字节和计算资源硬限制。

错误分类：transient、invalid_argument、query/code_error、data_quality、semantic_mismatch、permission_denied、budget_exceeded、outcome_unknown。重试分层且共享总预算，避免多层重试指数放大。

只向模型按需提供当前相关工具描述；可以 search_tools/load_tool，但执行权限仍由服务端固定。MCP 的工具名称、schema、版本和服务器权限都要登记；不因动态发现自动扩大权限。

保留现有 SQL 防护、工作区路径防护、凭据加密与 DNS/重定向防护。硬性授权失败必须 fail-closed；Hook 只能补充，不是最后安全边界。

### R06 — 远端计算优先、完整数据语义与受控多源分析

保留现有连接器，新增可运行Trino适配器，连接配置不只保存URL：包含engine version、catalog、schema范围、可信身份绑定、只读源权限、结果区、原生资源组、结果保留和认证方式。实际目标平台明确后按能力契约适配，不宣传未测引擎已支持。

**数据发现：**将同步枚举所有table/view和逐表取列改为按授权namespace分页/检索、懒加载schema、后台有界增量同步。已有企业catalog优先作为权威来源；不在注册时对所有表COUNT或SELECT采样，不因为旧实现只记录前200表就扩大为无界加载。schema cache记录watermark/版本/ACL，缓存也执行权限检查。

**执行位置：**标准指标优先指标API或正确版本预聚合；明细范围计算优先warehouse SQL；重型join、特征和大型计算走remote batch。小型完整结果或明确统计样本才进入bounded sandbox。本地入口遇到remote ref不能调用source_frames自动转Pandas；调用者必须显式选择经门禁批准的materialize_small。

**查询准入：**解析方言和只读AST、核验对象/字段权限、估算行数和扫描字节/分区、检查可能的笛卡尔积/高基数join/全局排序/不受限窗口、native EXPLAIN或dry-run，不默认执行EXPLAIN ANALYZE。WHERE出现日期不等于有效裁剪。估算unknown或过期时不能填0；按策略拒绝交互查询或进入具备真实上限的重任务队列。管理员可预授权批任务范围，不无限提高超时。

**资源控制：**同时记录估计与实际物理扫描/处理行、逻辑读取、CPU、shuffle、峰值内存、输出、网络、队列时间；不同引擎指标不同，不混淆计费字节和物理扫描。用引擎原生资源组/原生上限、任务配额和并发预留双层控制。取消有延迟，不能保证零超额；必须记录差异。缺少必需硬限额时warehouse高成本路径fail-closed，不能仅靠后台统计冒充强保证。

**结果：**使用第3.2节DatasetRef。小结果可有界持久化为保留类型的Parquet/Arrow；大结果由引擎写远端run专属结果区，控制面只保存授权引用、摘要和manifest。只有产物完成、schema与必要校验通过才设complete。源表快照不能复制进全局应用storage备份。

**准确性与完整性：**精确SUM/COUNT/ratio_of_sums不允许系统暗中改为APPROX或TABLESAMPLE；近似探索需在已确认契约授权内，输出算法/误差定义/适用范围，不把算法标准误写成95%置信区间。普通LIMIT不是随机样本；SYSTEM/BERNOULLI成本依引擎，不保证低扫描。用户Top N和系统截断分开；API分页未完成/总量未知如实登记。

**多源：**先各源过滤/聚合，再在实际支持的远程计算域关联；跨catalog join不等于总能下推到源。查看EXPLAIN/统计并施加迁移字节预算。文件小维表可经单独授权上传到scratch；大仓对大仓不自动拉本机。无可行授权路径时返回清楚限制并保留可完成目标，不生成错误替代结果。参考环境必须真实完成Trino+文件维表或API快照进入远端区的联合分析，并保留原本有界本地join。

**安全物化：**保留source只读，受控prepare_result/create_result内部操作使用固定scratch namespace和引用化输出，不放开模型SQL任意CREATE/DROP/INSERT。原生结果写入也检查run权限、前缀、对象数、大小、TTL、清理与审计。用户原始数据只读，数据区临时写是不同权限。

**预览和导出：**使用服务器分页，结果版本稳定、游标与权限绑定，避免深OFFSET反复重算；严格限制模型上下文、图表点、明细page字节和列数。下载巨型明细应创建受预算控制的远端导出任务/授权链接，不返回浏览器巨大JSON。小数据类型与中文、Decimal、时区、前导零、null、Excel公式缓存均真实round-trip测试。

**仓级画像和验证：**先用可获得的官方统计/元数据；必须扫描的数据检查在仓内合并，复用任务聚合结果；不对每个维度/图表单独重复全表COUNT。统计陈旧、抽样验证、只验证局部分区均明确范围和覆盖度。

### R07 — 数据目录、语义定义与来源代码理解

将现有 schema、知识条目、指标信息整合成授权数据目录，不另建一套不被 query_data 使用的展示目录。

目录覆盖表/字段、粒度、主键、关联基数、更新时间、质量、定义文档、历史已验证查询、来源代码引用与负责人等可获得信息。未知属性保持 unknown，模型推测与程序验证分开。

实现 MetricDefinition/SemanticModel 版本：measure、numerator/denominator、ratio_of_sums 等聚合语义、单位、时间/时区、维度、过滤、null/zero、关系及基数、适用范围、证据、状态。用受限 AST/参数化编译执行，不能 eval 字符串或拼接任意模板绕过 SQL 安全。

标准指标走已发布定义；探索指标是任务内 draft。AI 提出的定义进入候选，验证/审核后发布。更改正式定义生成新版本并使依赖缓存和结论失效。

支持从经管理员授权的 SQL、dbt 风格 YAML/SQL 或 Python 转换文件中抽取来源说明、依赖和过滤规则；只读解析，不执行来源代码。抽取结果保留文件 hash、位置、证据和不确定性，不能把模型解释直接当正式定义。支持扫描更新与 stale 标记。

检索权限在召回前和返回前都检查；采用现有关键词/向量混合能力和必要 rerank，embedding 不可用可退回可用文本检索但显示能力状态。不要把所有表schema每轮全部发送给模型。检索分catalog/schema/table/column层级，分页和top-k都要有上限；增量更新带watermark和失败续接。目录规模测试使用明确标注的合成元数据，不能用它冒充PB数据扫描实测。物化视图/聚合表只有定义、粒度、过滤和新鲜度满足任务时才可替代原表，不偷偷使用过期汇总。

### R08 — 有界Python与真正远端分布式分析

保留现有analysis_modules并建立方法能力表：输入类型、支持粒度、local/SQL/Spark后端、精确/近似性质、可分布式性、资源限制和验证规则。不是给每种Pandas算法贴上Spark标签；无法自然分布式的方法明确bounded-only，并允许Agent选择语义等价的可执行方法或报告条件不足。

**有界代码执行：**实现rootless container或等价隔离后端，固定镜像、无外网、非root、只读基础/输入、受限scratch/output、CPU/内存/PID/时长限制，无生产数据仓或模型凭据。Web/Agent及生成代码不得挂Docker socket；宿主代理只接收鉴权有限JobSpec，固定镜像/挂载根/资源，不接任意docker参数。容器不可用不回退主进程exec。所有对外产物检查路径、链接、格式、大小、来源与hash。

**输入门禁：**只接收经授权的bounded_file或小remote result物化，先核验行/字节/内存/列与总任务出口预算。评估解析后内存膨胀，不以压缩Parquet文件大小直接等同RAM需求。对无限迭代器、超大单值、逾期文件与半成品fail-closed。禁止把preview JSON作为完整训练集。

**远端批执行：**必须实现真实Spark+Livy Batch适配器：准备授权输入ref和代码/参数、提交、持久化batchId/appId、查状态、限量日志、取消、恢复核验、结果manifest、统计和错误映射。网络、存储凭据、proxyUser、queue、driver/executor资源由可信控制器确定，不能由模型任意指定。独立协议测试之外需要真实driver与多个executor执行。

**分布式方法最低集合：**远程过滤/投影/聚合/窗口、授权关联和特征构建；至少一个分组异常/趋势作业和一个真实MLlib模型训练/评估任务（线性或逻辑回归/聚类选择适合已有方法者）。预测一般先在仓内形成正确时间粒度完整序列，再在有界sandbox回测。数百万独立序列需分布式分组执行而不是逐条拉到控制面。保留现有分类/回归/聚类/预测/实验/情景分析功能，但各自受能力表约束，不承诺每种算法直接训练EB明细。

**隔离：**平台必须能落实任务身份/授权输入区/网络/目录/资源边界。若存储直接访问会绕过行列权限，先通过受控查询生成授权结果区，或采用平台强制身份机制；这类远端物化同样需要成本准入。共享集群无法隔离任意代码时用经审核JobSpec生成分布式作业，动态任意Python保留在有界sandbox；不能将AST黑名单当沙箱。必要环境未具备时将对应release gate记BLOCKED。

**建模验证：**ExperimentRecord保存数据/切分/特征/方法/参数/随机种子/环境镜像/验证指标/基线和条件。时间切分、分组泄漏、预处理fit范围检查齐全。样本不足、复杂模型无收益则按目标采用基线或明确部分完成。贡献/相关/模型解释/因果结论分开；A/B检验只在满足设计条件时作相应解释。

固定依赖并测试兼容，不生产任意pip install；Spark路径不得无界collect/toPandas。结果回传只包含有限模型指标、参数摘要和远端大产物引用。

### R09 — 独立验证和不可绕过的完成门禁

实现程序主导、可增加模型审查的 ValidationEngine。每个检查绑定规则版本、对象版本、输入和执行记录，结果为 PASS/WARN/FAIL/UNKNOWN/NOT_APPLICABLE 并带严重度和理由；未知不能自动通过。

原需求有“数据可信度评分”，必须保留为可解释规则质量分。实现版本化评分配置：逐规则权重、PASS/FAIL/WARN映射、未知/不适用处理，另显示检查覆盖率和存疑问题。可采用“已执行适用规则加权得分”和“已覆盖权重/应检查权重”两个数；全部未知则分数N/A。阻塞项FAIL/UNKNOWN不得因高分放行。分数不叫LLM自信概率、不称为答案准确率。

验证同样遵循远端执行和预算：合并检查、复用聚合、按快照/分区增量，不每条规则各扫一次PB全表；示例的随机抽样检查不等于全量正确性证明。估计行数、估计NDV不能用于精确声明主键唯一。范围缺失时交付质量限制，不自动pass。

五层检查：执行结构、数据质量、语义口径、分析方法、结果表达。至少检查唯一键、关联放大、总分一致、缺失/迟到分区、时间覆盖、分母与零分母、单位、重复计数、训练/验证泄漏、基线/回测、引用有效性、数值渲染一致性。

强制规则来自任务类型、已发布定义和系统策略；模型可以增加检查，不可删除、降低阈值或把 failed 改 passed。不能仅检查“有任意一个工具成功”就批准。

实现 finalize_analysis：检查契约覆盖、成果清单、数据完整性、当前版本、阻塞验证、证据和当前授权；通过才产生 immutable publication。失败返回具体问题供重规划，或形成明确标注的 partial 结果。

模型自然语言终止只产生候选回答/完成请求。正式数据结论必须通过 gate；SSE 可显示真实进度及经过授权、明确标注的草稿，但不得把原始模型流直接当正式结果。聊天最终消息、团队汇总、工作流交付、自动导出/通知都不能绕过发布。纯通用说明和明确草稿不需要伪装成已验证分析。

不能只用正则匹配报告中的所有数字实现“正确性验证”。关键数字应来自结构化 claim 与 typed metric refs；日期、版本和文字中的数字另行处理。模型审查作为补充，不能伪装成确定性证明。

### R10 — 证据图、可复现成果和统一渲染

实现DatasetVersion/远端SnapshotRef → Query/Code/Experiment → Validation → Claim → Chart/Report的来源和依赖图。只记录查询/分区/产物及关键结论层级，不能逐行集中保存PB数据血缘。Claim 应定位具体版本的数据结果键、列、单元格/聚合表达式或文档位置，区分事实/假设/建议/局限。

建立 ResultManifest：目标、范围/时点、关键指标引用、结论/证据、图表 schema、表格、代码、环境、验证和限制。极简结论、可视化看板和完整报告从同一清单渲染，不能各自重新编数。

图表类型由任务选择，字段/单位/排序/聚合校验；通用引擎不强制所有任务都是四图，但原需求的四图看板、四指标模板及四图拼合PNG必须实际支持并作为默认完整看板验收；不能用任意单图功能替代。图表数据和下载表格对应同一版本。保留现有 ECharts、PPT、HTML、Word/Excel 等能力；新增或补全看板 PNG、Notebook/脚本及复现清单导出。

导出文件实际可打开，内容与页面一致。验证 DOCX/XLSX/PPTX 的结构及关键内容，检查 PNG 真正渲染不是空白占位；Notebook包含代码/环境与授权数据引用，不嵌入凭据、不把PB/EB源数据打包；远端复现依赖有效快照/结果保留，过期应给出明确原因。远端结果表视图采用稳定分页；图表聚合在数据面计算。保留 CSV/Excel 公式注入防护和 HTML 内容净化。

草稿可以在经授权的工作区明确显示，不带正式认证状态。手动通用导出可以存在，但必须标识“用户提供/未验证”并执行权限，不能借此获得已验证发布状态或自动向外发送。

### R11 — 上下文工程、文档证据与多模态回退

ContextBuilder 每轮按需装配：契约、授权范围摘要、关键定义、计划/假设、阻塞验证、近期完整工具调用组、证据摘要、相关 Skills 与剩余预算。数据库和工具按引用载入，不把大表全塞入模型。

保留原始历史（不包括无界仓库数据），摘要作为版本化派生记录。按实际 tokenizer 或保守估算管理预算并预留工具输出/生成空间；摘要不得丢失关键限定、来源、尚未解决的冲突和失败检查。工具调用—结果组不可被截成非法协议。旧消息中的撤销权限内容不应继续注入模型；已发送给远端模型的历史内容不能承诺撤回，记录边界并对后续请求停止复用。

大输出保存可授权分页/检索的对象，不把执行失败包成 ok:true。返回 ref、schema、摘要、完整性和可读取范围。页面或模型预览不能代替真实全量数据。

支持 DOCX/XLSX/PDF/MD/TXT 及已有表格文件。保留 DOCX 标题/段落/表格单元格，PDF 页码/文本块/表格及页面引用，XLSX sheet/cell/range 和公式状态。文档解析需页数/解压/时间限制。

文本抽取缺失或表格不能可靠还原时，提供受控页图渲染与具备图像能力的模型适配，按页处理并保留位置证据；不能把看不清或未读取的图表编成数据。无图像模型时明确提示需补充可解析材料。OCR 仅在必要且配置允许时使用，不能成为所有文档的默认路径。

外部文档、网页、单元格、历史 SQL、工具输出和知识片段标记为不可信数据，不提升为 system 指令。保持系统指令与数据边界，工具执行侧再次约束。

### R12 — 受治理的记忆与 Skills

复用现有 memory/skills 实现和内容，建立清晰作用域：run temporary、user preference、workspace reviewed knowledge、published semantics/skills。记录 owner、ACL、来源、有效期、置信/验证状态和版本；低权限用户不能通过反馈写入所有人的系统规则。

用户能查看、修改、禁用和删除自身记忆；删除要使检索缓存失效。正式语义定义不直接存为一条无版本的普通记忆；单次口径修正不能自动覆盖全局。

Skills 使用现有 SKILL.md 并扩展版本、输入/输出契约、适用条件、权限、资源、验证规则、测试样例和兼容版本。执行依赖经审核的工具/隔离脚本，不获得额外授权。

实现完整 lifecycle：candidate → evaluated → approved/published → deprecated/rolled_back。候选生成、真实测试评估、审批发布、版本选择、回滚都有 API/界面与测试，不只写 Markdown 流程。原有技能按条件迁移并保留内容。

复用成功经验时检查数据源/语义版本和适用范围；失效经验不能因检索相似度高而优先采纳。不做在线基础模型权重训练，不允许 Agent 修改自身安全策略并直接上线。

### R13 — 按需多 Agent 与既有工作流统一执行

默认单主 Agent；独立工具可并行。仅当任务确实可拆、需要独立上下文或专门方法时创建子 Agent。继承并收窄 scope，父预算统一预留，限制深度/数量/时长。

子 Agent 使用同一 ModelAdapter、AgentLoop、ToolExecutor、RunStore 和验证协议，不保留一套无法恢复且不受发布控制的旧 team loop。每个子任务独立工作目录，输入只读，结果含证据和局限。主 Agent 合并冲突不能以投票替代验证。

保留已纳入范围的团队计划/成员配置、依赖、并行、重试及工作流 version/approval/pause/fork/manifests。删除已被统一内核取代的成员推理循环和重复执行器；普通确定性 workflow 调度不必改成 LLM 循环，但必须共用 Action/ToolExecutor/预算/结果门禁。通用团队邮箱或任务看板如无法证明是受支持功能的依赖，按 §2.5 合并或退役，而不是永久额外维护。

工作流是可复用技能或稳定作业定义；探索计划是任务执行时动态形成的对象，二者不得混为一谈。子任务输出改变时精确失效依赖节点；重试不能无条件把所有上游重跑。

### R14 — 增量分析、历史复现和版本失效

实现依赖指纹：输入数据版本、定义版本、代码/参数、模型/Skill 版本和策略范围。缓存读取再次授权；同样的 SQL 在不同快照/身份范围下不是同一个可复用结果。

追问按影响范围执行：改图表只重绘；改文案保留已验证数字；增加维度判断现有数据能否支持；改定义或筛选使相应下游失效；换最新数据生成新快照；分支分析保留原结果。

区分 replay（回看已存轨迹）、reproduce（固定已有输入/代码/环境重新计算）和 refresh（按最新数据重新分析）。模型输出可能非确定，不承诺同一句话逐字复现；数值重算精度和随机种子清晰记录。

外部API无快照、远端Iceberg/数仓快照已过期，或数据已按保留策略删除时，显示可复现范围和阻塞理由，不偷偷拿当前数据冒充历史复现。权限撤销后，历史、缓存、下载、预览和模型上下文都受影响。

### R15 — 生产授权、同空间细粒度隔离与安全

在已有 workspace/role 上补完整的 source/asset/artifact 访问策略；不能以“workspace 相同”代替本次 source scope 和用户授权。支持工作空间内用户私有与共享对象，明确所有权/可见性，默认不跨用户共享敏感记忆。

查询、schema、样本、画像、结果读取、文件工具、知识检索、缓存、图表、下载、报告、模型出站、分享、定时任务、子 Agent 和 MCP 都使用同一鉴权决策；禁止通过衍生产物绕过源资产权限。变更角色/权限后要实时生效或明确极短失效窗口并测试。严格即时撤销场景走鉴权下载代理；预签名链接须短时效并标明撤销窗口，不假设已发链接可以立刻失效。

对正式数据源提供安全的表/列/行范围限制：优先数据库原生只读视图/RLS/受限账号；若应用层实现，必须在受控源投影/参数化编译边界落实，不能靠 LLM 补 WHERE。不能允许执行账号关闭 RLS 或修改 session 安全上下文。

继承并增强 SSRF、DNS pinning、重定向、文件路径和凭据保护。别为了容器/集成测试简单关闭所有内网限制；仅给指定测试端点配置白名单。用户导入的代码/SQL/文档不自动变成可信插件。

审批包含动作参数 hash、契约版本、数据范围、接收方、授权人和有效期。批准后变更参数必须重新评估。模型传 confirmed=true 或自写 approval 记录无效。

敏感数据出站按模型端点许可和数据分类过滤，提供允许的本地/企业模型路径；日志不能包含密钥或默认全量数据。默认分析只读；发布、通知、删除和写回独立授权。

### R16 — 真实前端、API 与兼容体验

扩展现有前端，不创建另一个与主产品断开的管理页面。本文F01—F34为默认用户功能验收标准，不能以‘管理员可用SQL控制台完成’代替对话功能。需求确认默认必须出现；单智能分析模式；50MB五格式文件；三类和二级范围；三个成果Tab；四KPI/四图/明细表；两个Word/四图PNG；邮箱弹窗/真实附件/EML路径均要接通。用户必须可以完成：

- 查看动态计划与简要变更原因、假设/证据、真实工具执行和预算；
- 在任务运行中暂停、取消；原需求默认普通发送按钮禁用。高级控制入口可明确提交契约修订，不与普通重复提问混用；
- 浏览数据表、图表、SQL、Python、检查结果和相关数据/定义版本；
- 在摘要/看板/报告间切换并查看草稿/部分结果/正式成果状态；

不能添加必须按顺序点击的分析步骤向导作为 Agent 主流程。控制日志、技术细节折叠，默认体验仍是对话。

### R17 — 自动化、MCP、Hook 与外部交付

复用用于数据分析订阅、定时报告、看板刷新和成果通知的 scheduler/hooks/邮件组件。Feishu 等已经使用的只读数据连接与成果通知按范围集成；不保留与本产品无关的外部业务记录创建/修改工具。定时或更新触发的是明确 TaskContract，含来源、身份、频率、预算、接收人和有效期；支持禁用、取消、运行记录与重复事件去重。管理配置只由受授权 API 修改，不允许模型调用 configure_hooks 自行扩大策略。

调度执行前重新授权，任务所有者被禁用或权限撤销时不能继续访问旧数据。Agent 不得自行永久订阅全部数据。

MCP 授权和动态工具按需加载，返回内容视为不可信，不允许工具覆盖系统安全命名空间。Hook 异常不能导致权限或发布门禁 fail-open。审计/通知 Hook 与强制策略分开。

外部发送经独立审批或明确有效预授权，只发送 publication 绑定的确切版本。实现真实 SMTP/现有通知接口并用本地测试邮件服务或受控测试端点验证；不能把模拟 success 称为发送完成。未知发送结果进入 OUTCOME_UNKNOWN，不盲目重复通知。

邮件弹窗支持逗号分隔多个收件人、主题、自动填充摘要正文、三类附件默认选中及下载核对。正式SMTP/企业API确实发送附件；本地邮件客户端提供可下载含附件MIME的.eml和清晰兼容提示，mailto只是文本回退，不能假称通用浏览器可自动附带本地附件。F32/F33单独做浏览器与Mailpit或等价邮件服务集成测试。

用户直接人工导出未验证内容可保留，但不能由自动化冒充已验证报告推送。保留的飞书成果通知、邮件、分享链接均显示质量与版本。被退役的外部动作不得通过旧 Hook、MCP 别名或开关重新激活。

### R19 — 全链路测试、真实评估与防回归

2. 集成测试：模型可被脚本驱动，但数据库查询、物化、计算、验证、导出、恢复与浏览器行为必须真实执行。

### R21 — 旧实现退役、无关代码删除与仓库收敛（与功能同级必交）

#### R21.1 先建立清单，不凭感觉删

枚举 Git 跟踪的应用源码、路由、命令入口、插件/工具/Job 注册、前端模板与组件、静态资源、直接依赖、可选依赖、配置项、CI、打包脚本与测试。检查已记录的公开接口/CLI、已保存 Workflow/Skill 的符号名和远程部署入口。

对每个功能簇与实际删除/替换对象给出以下决议之一：

- `KEEP`：有当前目标、真实消费者与测试依据。
- `REFACTOR`：职责保留但内部修改；旧分支不继续并存。
- `MERGE`：多个实现归入唯一 owner，列出被删除项。
- `REMOVE`：确认死代码，或范围外能力已完成退役与必要迁移。

#### R21.2 删除认定需要多类证据

用 AST/import 分析、Ruff、Vulture 或等价工具发现候选，用 Flask 路由/CLI/工具注册枚举、前端 import/模板/CSS 引用、Job/Skill/MCP 配置、构建/镜像文件清单与运行测试补证。

扫描器可能误报动态调用。Flask 装饰路由、反射类、插件 entry point、CLI main、数据库迁移、作业脚本、pytest fixture、平台专用模块和本地 vendor 都可能没有普通 import 消费者。未覆盖也可能仅是缺测试。不能把扫描器置信度 100 当全系统无外部消费者的证明。

可维护精确到符号的动态入口例外，必须有 owner、入口依据和检测该入口仍存在的测试。禁止 blanket 忽略整个 backend、frontend、tests 或全部路由；禁止把所有告警自动生成白名单后称没有死代码。

#### R21.3 替换单元的完整闭环

每个垂直功能单元严格执行：

```text
保存基线与有效行为测试
 -> 实现目标路径
 -> 内部调用者/工具/前端/调度全部切换
 -> 在真实路径验证合同与安全
 -> 删除被替代的旧实现
 -> 删除其独占注册、提示词、配置、依赖、资源和打包规则
 -> 更新或删除对应测试（保留有效断言）
 -> 更新文档与迁移说明
 -> 复跑功能、安全、架构与清理测试
```

内部临时双轨只允许存在于未完成的施工阶段；最终交付不得使用 feature flag 重新启用旧循环或未经验证的执行器。迁移期临时开关必须在 M6 前删除或转为有明确消费者的合法 COMPAT。不要把旧功能改名成 `old_`、`fallback_` 后继续调用。

保留 API 名称不等于保留实现。确需薄 facade 时只做参数/返回格式转换与新模块调用，可有别名兼容；没有自己的循环、SQL 拼装、授权和完成判断。先迁移仓内消费者，再处理外部承诺，不能新代码继续依赖旧内部 facade 形成永久反向依赖。

#### R21.4 本次重点退役与合并

- 删除旧聊天/团队重复工具循环、请求内运行真值源、旧内存取消状态、被新 typed job 替代的闭包提交路径；线程池作为执行手段可以保留，不误认为 ThreadPoolExecutor 本身应删除。
- 把合法小数据 Pandas/DuckDB/CSV 逻辑集中到有界后端，删除通用函数内面对任意远端源自动取样并继续当全量的路径；不能删除所有 Pandas 导入来做表面整改。
- 默认退役通用 draw.io 创作工具及其独占资源；保留必要的历史图形成果数据，提供受限回看/下载，新的证据关系图不依赖通用编辑平台。
- 核对旧 GPU preflight/SSH/模型部署工具；与目标作业链无关的退役，有必要的健康探针合并到对应后端。不能把名为 remote 的模块一律删除，更不能删除新增远端查询和计算能力。
- 去掉主 Agent 任意修改应用文件/宿主环境、通用 Git/Shell、修改安全 Hook、外部业务表 CRUD 等范围外动作。授权数据源读取、任务沙盒文件输出、scratch 物化、记忆/Skill 管理与正式邮件是不同的合法动作，仍按要求实现。
- 通用 task/team mailbox 与新 Run/Plan/Subtask 状态职责重叠时合并；没有目标用途的 UI/API 退役。工作流历史/版本/审批/重试和团队受限并行作为有效分析能力保留。
- 删除仅服务旧行业演示的生产固定输出、假耗时与假成功。中性测试数据、独立金标、故障注入和确定性协议模拟留在 test/evals，不能因含 mock 字符串全部删除。

#### R21.5 连带清理必须完整

真实删除对应代码后，同步处理：Python re-export/注册/配置/类型/错误码、前端路由/菜单/按钮/事件/CSS、工具 Schema/别名/system prompt/Skill 引用、依赖声明/锁文件/可选 extras、Docker COPY/镜像/桌面打包、CI、README/示例环境变量/运维说明。

直接依赖无消费者才移除；依赖可能用于导出、解析、数据库驱动、运行插件或平台可选功能，不能仅在 backend import 中找不到就删。锁文件由实际包管理器再生成并验证，不手工删除随机 hash。保留仍分发第三方代码的许可证/NOTICE；清理不能变成删除来源署名。

删掉仓库中误跟踪的生成物时先确认可重建及无用户数据；生产构建从干净输出目录生成，不能依赖旧 build/dist 或本机残留 package。Docker 缓存/多阶段构建和桌面资源清单同样检查。不得顺便清理用户未跟踪文件、凭据、上传数据、远端 scratch 或历史成果；后者如需 TTL 是单独的受控生命周期服务。

#### R21.6 旧数据与 API 安全迁移

在旧数据库副本上测试迁移与恢复，保存真实历史记录的兼容读取/导出。旧不可恢复运行不得迁移后伪装恢复成功；旧未验证成果不得迁移成已验证。需要停机/排空正在运行任务时提供明确步骤。

删除旧 API 需判断是否已公开或在用户客户端/保存的配置中使用：无消费者的内部 API 可直接删；公开 API 做受限前向适配或文档化 410/迁移说明，不能只是返回 200 空结果。兼容接口也受新权限、数据大小与发布门禁约束。

数据库旧表/迁移脚本不是普通死代码。先采用增加/迁移/验证的兼容步骤；已证明无数据依赖、保留政策允许、恢复路径验证后才能安排 schema 收缩，禁止为了减少表数自动 DROP 用户数据。

#### R21.7 清理自动验收与报告

实现 `scripts/audit_repository.py --check --report <path>`（可复用现有审计器并记录最终名称），至少真正检查：

1. 已删除符号/工具/路由/前端模块没有未解释的活动引用。
2. 仅有一套主/子 Agent 多轮工具循环与统一执行/验收边界；不是简单统计 while 字符串。
3. registered tools、routes、job handlers、provider adapter、前端入口与允许清单一致。
4. 声明移除的依赖/资源不在最终安装或打包清单；保留动态入口有真实测试。
5. 兼容项有消费者、边界和移除条件；最终不含遗留第二内核或不安全 fallback。
6. 清理清单中的实际删除/重构有差异与测试证据，未处理的高风险条目不得输出整体 PASS。

审计工具无权自动批量删除生产文件。它提供问题报告和非零失败；代码删除由本任务按清单执行。static 扫描与行为/构建/安全测试分列，不能用工具退出零证明所有代码都有效。

`verify_advanced_agent.py --profile repository-audit` 聚合 C01–C24；`release` 必须包括它。报告实际新增/修改/删除文件、符号合并、直接依赖/产物变化和测试替代关系；行数与包体积只作观察，不设置“至少删除30%”之类目标。可增加审计工具自身的负样本测试，确认故意引入旧循环、残留路由和过期白名单时会失败。

“清理完成”定义：范围清楚，已识别待退役实现已移除，必要兼容有证据，活动入口与构建无无主残留，全部指定验收通过；不是绝对证明未来任何情况下都不会发现新的无用代码。


## 5. 数据/动作协议最低要求

下面是最低语义，不是要求所有类必须采用完全相同名字。实现可以优化，但不能删掉关键状态与边界。

### 5.1 RunContext（服务端可信）

```text
run_id, session_id, actor_id, workspace_id,
contract_version, policy_version, source_scope,
allowed_tool_ids, parent_run_id, budget_id, lease_epoch
```

身份、权限和预算必须从服务端状态读取，不能接受模型覆盖。任务选定数据源范围与用户全部授权范围分别维护。

### 5.2 ToolResult

```text
status: SUCCEEDED | ACCEPTED | WAITING_APPROVAL | FAILED | UNKNOWN
logical_action_id, attempt_id, job_id,
output_refs[], schema_refs[], preview,
completeness, warnings[], error_code,
provenance_ref, validation_status
```

query 成功不代表 validation PASS，ACCEPTED 不代表作业完成。错误对象落盘后仍然是错误。

### 5.3 核心执行顺序不变量

```text
检查控制消息/当前授权/预算
  -> 装配受控上下文
  -> 模型完整输出
  -> 校验工具协议和终止原因
  -> 持久化 decision 与 action intent
  -> 原子预算预留与待执行记录
  -> 真实执行/提交作业
  -> 持久化真实结果或 unknown
  -> 运行必要检查/更新证据与失效状态
  -> 下一轮决策/等待/澄清/完成请求
```

这只约束运行协议。工具顺序、是否 Python、是否多 Agent 和具体分析方法由任务动态决定。

### 5.4 恢复不变量

同一外部效果允许至少一次派发语义，但必须有可核验/幂等手段；不能声称所有外部系统都恰好一次。文件输出先临时目录、原子完成标记再登记；通知等无法核验状态必须保留 unknown。恢复后旧 lease 的写入和动作提交被拒绝。

### 6.2 可实现性与规模证明的分级结论

- 功能/协议：真实数据库和浏览器工作流证明F矩阵；脚本化模型只能证明工程路径，不证明自主分析质量。
- 参考分布式环境：真实Trino/Spark/Iceberg工作证明适配、路由、权限、完整性、远端结果和恢复语义；测试数据规模如实写出。
- 性能渐进：先在受限测试集证明分区裁剪和传输边界，再在有授权的更大规模测扫描、shuffle、资源和并发。数据量、文件数量、分区分布、倾斜和冷热缓存都记录，不把外推当实测。
- 目标生产：核对实际引擎版本、数据目录、身份/行列权限、结果区、认证、预算和SLO；缺任何必要接入条件就BLOCKED对应目标，不宣称PB/EB已上线。

不存在‘所有架构功能写完即可保证任意EB分析秒级完成’的验收。完整实现要求功能和执行协议真实，规模性能还要与现有引擎/集群能力一起验证；这个边界不授权删除任何必交代码。
