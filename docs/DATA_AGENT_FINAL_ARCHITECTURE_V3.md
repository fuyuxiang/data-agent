# Data Agent 最终改造方案 V3

**项目：** fuyuxiang/data-agent
**日期：** 2026-09-06
**定位：** 业务无关、自研运行层、面向 PB/EB 现有数仓的自主数据分析系统。
**交付性质：** 本文件是技术方案，不是已完成的源码改造或性能测试报告。完整执行要求以同包 `CODEX_DATA_AGENT_FINAL_V3.md` 为唯一规范。

## 1. 最终决策

在当前仓库增量改造，不另起产品，不引入 Echo、Pi、LangGraph 等 Agent 运行底座。保留适合目标的产品能力和基础技术栈，合并重复实现，退役无关功能，删除被替代的旧路径。

最终应是一套产品、一套主/子 Agent 决策内核、一套有权限与预算的工具执行协议、一套正式成果验收机制。不同模型适配器、数据引擎和确定性工作流不等于多个 Agent 内核。

先进性通过可观察行为证明：发现定义错误会修订计划；出现数据质量问题会停止不成立的分析；大数据在远端计算；结果可以追溯与局部重算；任务中断能够核验实际作业；经验复用不会越权或污染正式口径。

**必须同时完成三件事：原需求通用功能、真实的仓侧执行与可靠运行、旧代码清理。**“实现了接口”不能替代前两项，“不再显示菜单”不能替代第三项。

## 2. 原需求与本方案的关系

功能来源为用户上传的《智能分析 Agent 需求规格说明书》§1.4、§4—6，完整清单 F01—F34 已嵌入执行任务书。引用的文件页为会话渲染的34页版本，不是页脚页码。[S1]

| 需求理解与一次确认 | 先生成简短应答、流式理解依据、四段可编辑内容；生成完成后可确认；重新描述回欢迎页；确认后锁定版本。 |

| 深度分析 | 多维下钻、贡献与异常、趋势、Python/机器学习；方法选择与输入规模匹配，结论依赖真实证据。 |
| 记忆与技能 | 反馈/偏好/规则修正有可查看记录；候选技能经过测试及适用范围治理后复用；删除与回滚可用。 |

| 成果 | 极简结论/可视化看板/完整报告三个 Tab 按需生成；支持四指标、四图模板与授权分页明细。 |

### 明确的解释与增强

原文“思考过程”实现为面向用户的需求理解依据与决策摘要，保留流式/折叠，不展示隐藏推理。模型解释真实事件，不能创造执行状态或耗时。

原文评分保留，但采用版本化规则质量分与检查覆盖率，不能当作答案正确概率。原文演示发送和历史回放提升为真实实现；原文二期范围选择纳入最终交付。

原文一次需求确认保留为默认流程。它不要求系统允许越权或静默改目标；新重大歧义需要明确修订，日常不再机械增加计划/SQL/结果三次审批。

三类成果按需生成，四卡四图模板必须可用，但缺少有效数据时不编数凑卡片。普通 mailto 不能保证跨客户端自动携带附件；正式附件发送由服务器完成，客户端另提供 EML 并如实说明支持范围。[S10]

## 3. PB/EB 的准确边界

PB/EB 指已有数据平台的存量，不是要求每次提问扫描全部数据，也不等于本地服务器处理同样体量。

分别记录：仓库存量、任务扫描量、中间交换量、结果量、跨域传输量、本地解码内存、并发、排队与时延。规模结论必须注明实际测到的范围。

完整分析是“在已确认范围完成必要计算”。一亿条记录经精确聚合得到100行结果，这100行可为完整结果；先取前1000条明细再汇总不能冒充全量。

三条执行路线：

| 路线 | 适用任务 | 结果位置 |
|---|---|---|
| 仓侧 SQL / 指标 API | 过滤、聚合、窗口、变化贡献、可表达的异常及验证 | 小结果可回传；大结果留在授权结果表/存储。 |
| 远端分布式作业 | 重型关联、特征计算、批量趋势/异常、支持的分布式建模 | 远端模型/数据产物；Agent只接有限统计和引用。 |
| 有界隔离 Python | 小上传文件、完整聚合序列、符合设计的样本、绘图及局部分析 | 限额文件和可验证结果。 |

算法库保留，但每个方法有 local/SQL/Spark 支持矩阵。不能把 Pandas 算法包进 Spark 提交器就称其可分布式，也不能用未声明样本替代用户要求的完整范围。

## 4. 目标架构

```text
Vue 分析工作区：对话/确认/过程/三类成果/证据/历史
                           |
Flask API：身份/任务创建/事件订阅/控制/授权下载
                           |
自研 AgentLoop + ContextBuilder + Plan/Hypothesis
                           |
RunStore/Runner：持久状态、动作、预算、等待、恢复
                           |
ToolExecutor + ExecutionRouter：统一策略与执行准入
          /                |                 \
  Warehouse SQL         Remote Batch       Bounded Sandbox
  现有数仓/指标API      分布式平台          小型授权输入
          \                /
       原生数据、快照、run专属结果区、对象存储
                           |
  DatasetRef -> 验证 -> Claim -> ResultManifest -> 发布
```

API、Runner、查询/作业组件和小数据沙盒按进程与安全边界分离；业务模块不必都成为微服务。模型 SDK、数据库驱动、SQL解析、容器和计算引擎复用成熟基础组件。

SQL 逻辑目标由 Agent 选择；物理执行优化由引擎完成。执行器检查计划与能力，不能把 SQL 里写了 WHERE 当作已成功下推；下推取决于实际连接器和引擎计划。[S7]

### 控制状态

`AgentRun` 是一次正式分析，不是聊天消息；`analysis_runs` 等已有算法记录的语义不直接覆盖。

核心对象为 TaskContract、PlanRevision、Hypothesis、Decision、Action/Attempt、ExternalJob、DatasetRef、ValidationResult、Claim、Artifact/Publication、BudgetReservation、Event/Outbox。

执行状态、成果完成程度、质量状态和停止原因分列。查询成功、作业提交成功、结果完成、质量通过与正式发布是不同状态。

### 决策循环

```text
处理用户控制/当前授权
 -> 装配必要上下文
 -> 获取完整模型响应
 -> 校验工具调用与结束原因
 -> 持久登记动作并预留预算
 -> 执行或提交远端作业
 -> 保存真实结果/错误/未知
 -> 验证、更新证据与失效关系
 -> 继续决策/等待/澄清/申请完成
```

流式工具参数未完成不执行；模型不再调用工具不等于验收通过。运行协议固定，分析步骤不固定。简单问题确认后可直接使用标准指标；复杂问题依据事实增加、取消或替换任务。

### 任务恢复

按逻辑 action_id 区分不同 attempt，与外部 job_id 关联。先登记再执行，结果先保存再唤醒。长作业等待不消耗模型轮询。

Trino 的查询执行组件需继续履行 nextUri 协议，不由浏览器维持；不能认为保存 query_id 就保证任意断点恢复。[S8] Spark/Livy 的 batchId、appId 与真实结果清单同样需要核验。

恢复先判断已完成、仍运行、未提交或结果未知；对不确定的发送/写入不盲重试。仅保证实际后端支持和已测试的语义，不声称通用 exactly-once。

## 5. 数据合同、权限与验证

### DatasetRef

记录远端关系/表/对象清单或有界文件、授权来源、执行引擎、schema/粒度、快照/水位、查询/代码版本、实际范围、结果保留期、来源证据。

计算状态、范围完整性、精度模式分开：planned/running/complete，complete/partial/unknown，exact/approximate/sample_based/unknown。

远端大结果进入旧接口时，必须显式远端路由或拒绝，不能自动触发 `pd.read_csv`、`fetchall`、`collect`。转换为本地输入须提前核验并在运行中限制行、字节、单值、列数、内存、时间和累计出口。

### 目录与语义

目录按权限分页检索、按需展开表结构、增量更新，不在连接时全仓 COUNT/采样。正式指标定义包含分子/分母、ratio_of_sums、粒度、单位、过滤、空值和版本；来源代码只读解析，模型候选不会自动覆盖正式口径。

### 查询与临时结果

SQL AST、对象权限、方言、EXPLAIN/dry-run、成本新鲜度、关联风险、预算与原生资源组联合准入。成本未知不能填零；LIMIT 不作为扫描预算。

源表只读。可信物化服务可向私有 run 专属 scratch 写结果，绑定配额/ACL/TTL；模型不能自行选择任意库、表或路径写入。跨源大关联使用有授权的远端计算域；无可行域时明确限制，不自动搬本地。

### 安全代码执行

有界代码在固定依赖、网络/文件/CPU/内存/PID/时间受限的环境中执行；不可把主进程 exec 当回退，也不可给生成代码 Docker socket 或生产凭据。

Spark 作业必须通过平台身份或授权输入区防止绕过仓库行列策略。共享平台不适合任意代码时，提供审核后的参数化分布式方法模板；仍实现真实远端计算，不返回假成功。

### 独立验证与成果

验证覆盖执行、数据、语义、方法和表达。规则绑定版本与范围，可合并到仓侧聚合；抽样检查不是全量证明。阻塞规则失败/未知不能用总分补偿。

Claim 将关键结论关联到数据版本、结果键、查询/代码、定义与验证。ResultManifest 是摘要、图表、报告及导出的共同来源。

完成请求必须经过发布门禁。草稿可明确展示，但未经验证的数字不能因为模型停止、旧 API 导出或旧邮件 Hook 获得正式状态。

### 权限持续生效

用户权限、任务选择范围、Skill/子任务范围取交集。目录、样本、查询、缓存、记忆、结果、历史、模型出站和下载都检查当前授权。

严格即时撤销的下载使用授权代理；短期预签名链接的实际撤销窗口必须说明。已发给模型/收件人的内容不能承诺撤回。测试模式不得额外放行。

## 6. 当前项目的具体改造和清理

以下是关键路径静态核对后的建议，不是全仓已证实的死代码表。实际编码前应按真实 HEAD、路由、工具注册、前端、配置及使用者重新核对。[S2—S6]

| 当前职责 | 改造 | 必须删除或收敛的内容 |
|---|---|---|
| `agent_runtime.run_conversation` 的多轮交互 | 抽到独立于 Flask 的正式内核 | 被替换的旧循环、单独完成判定与旧 fallback。 |
| `teams.run_team_member` 的独立循环 | 成员变为受限 child run | 独立模型/工具重试、预算与状态逻辑。 |
| conversation API 在 SSE 请求中执行 | 创建任务与订阅事件分离 | 请求寿命决定任务的路径、内存取消真值源。 |
| jobs 的工作闭包与孤儿标记 | typed job、动作恢复、外部作业核验 | 无法重建的旧提交主路径；线程池可作内部实现保留。 |
| 数据结果以 DataFrame/CSV 为中心 | DatasetRef 与多后端路由 | 任意远端源自动取样/全量下载的泛化桥接。 |
| 工具 Schema 与分派、多种旧别名 | 单一注册、授权执行、清晰能力声明 | 退役工具/过时提示/重复类型/测试授权旁路。 |

现有单数据库查询已有原生执行路径，不能笼统称为全部本地 SQL。需要改变的是后续数据处理和结果语义。现有安全、算法、格式库与有效历史功能应优先复用，不需从零再写。[S4]

## 7. 哪些保留，哪些合并，哪些默认退役

### 保留功能而允许替换实现

保留 F01—F34；保留有效的数据连接、统计与机器学习、记忆/知识/Skills、分析型工作流与受限并行、图表/Office/PPT/数据导出、模型接口、身份与凭据、审计/备份、必要的离线/桌面交付。

这些是目标能力，不是“无关代码”。但所有路径受同样数据合同与门禁约束，不因历史上已存在而豁免。

### 合并重复实现

聊天/团队多轮循环、状态与任务提交、schema/工具类型、权限检查、结果验证、报告渲染等合并到唯一职责 owner。稳定工作流的确定性调度可以保留，不必强行把每个节点交给模型。

### 默认退役的额外产品能力

| 候选能力 | 原因 | 不能误删什么 |
|---|---|---|
| 通用 draw.io 创作、任意图形模板编辑 | 不属于数据分析闭环必要能力，可移除独占工具与大资源 | 数据图表、证据/依赖展示、用户旧图形成果。 |
| 通用 GPU 主机/模型部署管理 | 当前重点是分析，不是算力运维产品 | 实际数仓/Spark 作业提交、必要能力探针、现有模型 API。 |
| Agent 修改应用代码/宿主文件、通用 Git/Shell | 非目标能力且扩大攻击面 | 授权文件读取、沙盒代码执行、受控输出与用户文件。 |
| 外部业务系统表的任意 CRUD | 默认分析只读，结果发布与源业务写入不是同一权限 | Feishu 等只读数据连接、邮件与已配置成果通知。 |
| 通用邮箱/独立任务平台、旧演示页面 | 与 Run/Plan/分析工作区重复或无目标依赖 | 团队受限子任务、状态、历史、真实通知。 |
| 被替换的旧 Agent、旧 UI、旧配置与重复适配 | 已有明确新 owner | 真实公开合同需要的薄兼容与迁移链。 |

这些是范围选择，不是“当前完全没人用”的事实断言。当前 `meridian_remote_runner.py` 是 CUDA/PyTorch preflight，不能凭文件名当作训练服务器，更不能当 Spark 实现；应按真实调用职责决定删除或合并。[S6]

用户已授权清理无需保留的实现。对明确的无用代码不用每删一个文件都再次询问；涉及真实外部使用者、生产数据或不可逆影响时，必须明确迁移或记录待决，不盲删。

## 8. 清理是一条有证据的研发流程

### 8.1 清单

先建立 FEATURE_SCOPE 与机器可读 CLEANUP_MANIFEST；每个对象登记 KEEP、REFACTOR、MERGE、REMOVE、COMPAT 或 NEEDS_REVIEW，以及入口、原因、目标、替代路径、数据影响、测试与状态。

静态工具用于发现候选，必须结合动态注册和行为证据。Vulture 官方也说明动态语言可能漏检，隐式调用可能误报；Flask 路由、CLI、fixture、Job/Skill 注册不能仅凭没有 import 删除。[S9]

### 8.2 垂直切换

新路径实现→迁移调用者→合同和安全回归→删除旧实现→清除独占工具/资产/依赖/配置→重建与检查。每一阶段执行，最后再做全仓收敛，而不是最后才考虑清理。

不能把旧代码搬到 legacy/archive、改成注释、改名 `_old`、置于默认关闭的开关后，声称已删除。Git 历史用来保存源码历史，运行包不应承担源码档案库职责。

### 8.3 兼容

内部调用者统一迁移；公开 API/CLI、已保存工作流的工具名和历史格式按合同处理。必要 adapter 只转换格式并调用新内核，不独立推理、查数、授权或发布。

兼容项记录消费者、owner、测试和到期版本/事件。到期未删除进入 CI 问题。没有依据的无限期兼容属于未完成清理。

### 8.4 测试与数据

允许删除已退役功能专属测试和改写旧实现细节测试，但必须有映射；不能通过删仍有效的安全断言降低门槛。mock、金标与故障夹具放测试区，不是生产废代码。

代码清理不删除上传文件、历史成果、凭据、源仓表、保留中的快照和数据库迁移。旧结果保留已知质量状态，旧运行不被虚构恢复成功。数据库收缩采用独立迁移流程，而不是顺便 DROP。

### 8.5 构建与验收

检查后端 import/re-export、Flask 路由、工具与Job注册、前端模板/菜单/CSS、Skill引用、依赖锁、Docker/桌面清单、环境变量、README 与许可证。

从干净输出和新环境安装构建，防止旧缓存使被删代码仍可用或仍进入包。`audit_repository.py` 给真实错误并非自动删除工具；其负样本测试应证明残留注册、死导入和第二路径能被发现。

不设“删掉30%代码”指标。评价依据是已识别废实现清零、必要兼容有主、没有绕过路径、目标功能回归、构建干净，以及全部C验收结果。

## 9. 部署与实现顺序

保留 local 与 warehouse profile。控制状态初期可以单主 SQLite，必须明确实例所有权与恢复；PB/EB 源数据不自动意味着控制库需要分布式。实际多副本和高可用取决于并发/SLO，需要另有真实实现与故障测试。

参考数据面为 Trino + Iceberg + Spark/Livy；锁定兼容版本与共同 catalog/存储或显式转换路径。SQL 至少两个 worker、Spark 至少两个 executor 有真实执行记录。参考成功不要求客户迁仓，也不能代表客户目标环境已经兼容。

M0 范围与基线；M1 唯一运行内核；M2 远端数据引用与执行；M3 规划验证成果；M4 全部原需求交互；M5 实际集成与评估；M6 最终清理和干净构建。每阶段都包含对应旧代码退役。

优先尽早跑通“确认—真实仓侧小聚合—验证—四卡/图表—Word/PNG—邮件—追问”的代表路径，再扩展全部变体；这只是研发顺序，不是产品固定流程，也不授权最终只交这一条演示。

## 10. 完成定义

执行任务书有21项工程要求、34个功能组、64个核心场景、30个大仓场景、24个清理场景。场景数不等于测试函数数；每项要有真正断言与执行记录。

| 验证层 | 能证明什么 | 不可替代什么 |
|---|---|---|
| 协议/单元 | 模型分块、工具消息、状态和策略 | 真实模型的分析质量。 |
| 功能集成 | 真 SQL/Python、浏览器、图表、邮件、迁移 | 目标 PB/EB 集群性能。 |
| 参考分布式 | 多 worker/executor、远端结果、作业协议、边界 | 任意数仓兼容或多主机容灾。 |
| 真实模型 | 固定任务与独立金标下的准确性/稳定性/成本 | 所有自然语言任务必然正确。 |
| 目标平台 | 指定引擎/版本/身份/结果区上的接入 | 未测规模的吞吐与延迟。 |
| 规模 | 实际扫描/输出/并发/资源/时延范围 | 只靠仓库存量或TPC参数外推的能力。 |
| 仓库清理 | 指定旧实现退役、无已知无主残留、构建/回归通过 | 数学证明任何代码未来都不会成为死代码。 |

实现状态和测试状态分列。未编码是 NOT_IMPLEMENTED；缺凭据/资源导致未测试是 BLOCKED；执行失败是 FAIL；只有真实通过才是 PASS。

`release` 包括功能、参考数据面、真实模型、邮件、迁移和清理验收。目标平台与 PB/EB 规模分别报告，未经授权不扫描生产大仓。遇到外部条件阻塞仍继续完成其他可实现内容，不把必交功能写成 TODO。

**最终交付应包括真正可用的改造、经过验证的代码退役、迁移/启动/验证命令、清理与兼容清单，以及真实的未完成/未验证边界。**
